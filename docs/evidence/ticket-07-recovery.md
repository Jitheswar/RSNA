# Ticket 07 damaged-input recovery evidence

Recorded 2026-09-11 (Asia/Kolkata). This is public-safe implementation and
synthetic-fixture evidence. It contains no competition identifiers, reports,
raw paths, or private failure records.

## Implemented seam

The real-inference runner now uses the recoverable series-loading mode. Each
manifest entry gets one deterministic attempt through the pinned decoder
attempt order. Typed damaged, unsupported, and validation failures are kept
with the source entry and skipped when enough valid, geometrically ordered
slices remain. A series below the frozen minimum is rejected explicitly. The
strict `require_complete_series=True` loader option remains available for
callers that need ticket-05 all-or-nothing admission.

The shared model receives the surviving series and its existing slice/series
masks. An all-invalid study still receives one output row, using a
`ReferenceFallbackPrior` rather than silently disappearing. Unexpected
decoder infrastructure, programming, model, cache, and configuration errors
remain fatal.

Emergency scores are computed independently for each target from an explicit
eligible reference-label set:

```
(positive + alpha) / (positive + negative + 2 * alpha)
```

with `alpha=1` by default and `0.5` when that target has no known eligible
reference label. Held-out identifiers cannot overlap the eligible set. The
CLI accepts private inventory/fold-shaped JSON and admits only complete gold
or reference rows from those formats; report-only memberships are ignored.
For non-fold label files, the eligible study list is mandatory. A fold-shaped
manifest can derive the training-reference set and held-out exclusion from an
explicit `--fallback-held-out-fold` selection.

## Demonstrated scope

Synthetic integration tests exercise:

- one damaged/missing slice with three surviving slices, yielding a model
  prediction and an `accepted_partial` series rather than a full-study
  fallback;
- a missing series and a study with no series, with both rows retained and
  prior-backed fallback scores;
- private diagnostics containing the study, series, affected source entry,
  decoder, bounded attempt list, typed reason, recovery action, remaining
  usable-series count, and fallback status;
- aggregate public numerator/denominator and rate for full-study fallback,
  separately from slice and series loss;
- exclusion of report-only rows and held-out gold rows when the CLI reads a
  fold-shaped label file;
- private geometry/preprocessing rejection records with affected files and
  admission-stage errors; and
- public and private pending-investigation status for every nonzero fallback
  case; no case is claimed unavoidable by synthetic evidence;
- an unexpected decoder `RuntimeError` propagating as a fatal failure instead
  of becoming a successful universal-fallback output.

The bounded adapter is `slurm/run_ticket07_recovery.sbatch`. It requests one
`cluster1-cpu` node, 16 CPUs, 64 GB, six hours, and no exclusive allocation.
Identifier-bearing manifests and diagnostics remain under private paths; the
public evidence generated by the runner omits them.
