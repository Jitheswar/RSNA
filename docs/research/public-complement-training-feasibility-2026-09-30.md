# Public complementary training feasibility — 2026-09-30

## Decision

**An exact reproduction of the stronger forks' independent training arm is presently infeasible. A single frozen ConvNeXt Tiny feature experiment is feasible to propose, subject to checkpoint admission and measured CPU throughput.** Public source establishes architectural diversity and broad report supervision as plausible hypotheses; it does not establish that an independent model can close the stated author-public `0.943 → 0.961` gap. The D4 author's 0.943 is not our score; its exact v1/v2 attribution is recorded in [the frontier audit](public-frontier-options-2026-09-30.md).

At dispatch, the shared ledger had a 72,000 allocated-GPU-second cap, 10,126 charged and 57,600 reserved for pending scoring submission `56705536`: **4,274 seconds unreserved**. Pending scoring prevents concurrent GPU work. Terminal accounting must reconcile actual use before any new GPU reservation. Research downloaded only exact named source/history files and model metadata; no weights, training, notebook launch, push or scoring action occurred. Ticket 39's choices remain preserved; this proposal does not reopen Ticket 40.

Their exact scripts and executed histories are primary evidence, saved under `artifacts/private/external-notebook-audit/frontier-2026-09-30/complement-training/`.

These are real image-training recipes, rather than reference-only fitting. Their gold58 metrics are **selection AUCs**, not OOF. The best Global96 single epoch reports 0.927404; D4 reports 0.930171 for selected adapter/SWA predictions. Neither can be used as an unbiased comparison to our corrected three-fold OOF. Primary scripts explicitly compute reference membership from all twelve official nonmissing labels, exclude those 58 from gradient training, and use them to rank/save checkpoints. A report holdout is not present in the executed configuration.

D4's elapsed field is cumulative across the epoch loop; summing its 24 entries would overcount. Its 2,703.55 s endpoint excludes earlier parent initialization/parity checks and subsequent final SWA-selection work, so it is not a complete allocation charge. Repair/residual epoch timing sums likewise exclude unrecorded startup/checkpoint overhead.

### Pretraining and unavailable training inputs

The exact CoAt architecture is `coatnet_rmlp_2_rw_384.sw_in12k_ft_in1k`. Its [maintainer model card](https://huggingface.co/timm/coatnet_rmlp_2_rw_384.sw_in12k_ft_in1k) identifies ImageNet-12k pretraining, ImageNet-1k fine tuning and Apache-2.0 licensing. The public trainer requires its own serialized pretrained file with SHA-256 `d083f0c8ae4a2687802723fa9a31ddb66ead1ee3d950b66e46af62731dbf1279`. Current upstream weight manifests have different byte hashes; tensor equivalence was not checked and should not be assumed.

All four recipes require `targets_dualsharp_soft.csv` and `targets_dualsharp_weight.csv`, hashes `3b360a6a029ee1864324fba0e895dd84065351495ec6bcff109cd5d2888c888f` and `cc1f5012fe41e71f6ce3d86358862f5bfa65d3d16864ef84a49eeca9b4fac3cb`. **Neither file nor its generating recipe is in the three retrieved package inventories.** They cannot be equated with another public LLM label table merely because both contain report probabilities. Exact model/prompt/service provenance and reference-set influence remain unknown for these dualsharp files.

The publisher cache is also absent: native 384-pixel uint8 `slices_384.npy`, 679,023 slices, 100,126,015,616 bytes, SHA-256 `28064dec974b025cb79f1de2676aa6cbccf065332e4e014371ef7a8fb6518d21`, with nine index/geometry/mask sidecars. Public scripts describe canonical sagittal handling, source depth coordinates and physical 130 mm triplet crops; our existing 224-pixel whole-field cache does not reproduce this representation.

CC0 declarations cover the uploaded packages; they do not supply missing files or establish rights/provenance of undisclosed labels. Competition images/reports remain competition inputs. The prior primary [competition-rule audit](public-frontier-options-2026-09-30.md) records public-code/external-resource conditions; new public label admission must also satisfy the repository's fold-specific source policy. [The separate public LLM-label audit](public-report-label-source-2026-09-29.md) found gold58-based label development and unresolved production provenance; those labels are still research-only.

### Feature caching

Global96/Repair rank-loss replay uses detached features **within an optimizer update** while BCE updates the backbone. Those features cannot be reused across later updates or folds with adapted encoders. D4 does freeze its parent, making deterministic feature caching possible in principle, but its exact trainer re-encodes random sampled/intensity-jittered images each epoch. Replacing that augmentation with fixed features changes the recipe. A gold58-selected public parent also prevents treating its held-out reference predictions as clean independent OOF evidence.

## One bounded independent proposal

Propose **one frozen `timm/convnext_tiny.fb_in22k_ft_in1k` encoder**, followed by the existing anatomical pooling and matched reference-only/report-supervised CPU heads. This tests whether a different public representation adds useful image signal. It does not reproduce the private 320/384-pixel, 24-slice triplet models.

The [maintainer card](https://huggingface.co/timm/convnext_tiny.fb_in22k_ft_in1k) declares Apache-2.0, ImageNet-22k→1k pretraining, 768-dimensional embeddings and a roughly 28.6-million-parameter architecture. The [original implementation](https://github.com/facebookresearch/ConvNeXt/blob/main/LICENSE) is MIT. The exact upstream API manifest pins revision `bc48a87f119bae1b06418f5340bfa97ef75d4609`; `model.safetensors` is 114,374,272 bytes with SHA-256 `77b619e187de71bce58721689da0c009e84cc20677293d7d43105307e34d868a`. **These are metadata identities; checkpoint admission/download has not occurred.** Its small config confirms 224-pixel training inputs, 288-pixel default test inputs, ImageNet channel normalization and 768 output features.

Use the already prepared 224-pixel whole-field single slices, geometry ordering, rounded-uniform sampling, maximum 16 series × 8 slices, missing-plane handling and fixed plane/series pooling. Replicate each single slice into three channels and fingerprint any model normalization explicitly. Fix 224-pixel extraction rather than silently using the card's 288-pixel test setting. Preserve Ticket 39 and introduce no adjacent-slice channel context or Ticket 40 experiment. Freeze encoder parameters and buffers so one deterministic cache can serve every fold; held-out images may be encoded solely for prediction, with no fitting or normalization statistics taken from them.

The current local [feature manifest](../../artifacts/private/ticket36-expanded-supervision/features/feature-manifest.json) proves **4,228 studies** with verified source/array checksums, superseding the original spec's stale 158-study preparation description. It does not prove all 4,407 publisher studies are prepared. Ticket 44's actual fold-specific report arms use 2,731 / 2,846 / 2,749 weak studies plus 38 / 39 / 39 reference-training studies. Reuse those precise membership/mask policies and the admitted report artifact `33ae5e71499cf91fcc825d903e07d8519557e2bb2e1a40e64891f4c0fe00f6df`; do not admit dualsharp or another new public label source.

### Exact proposed amendments and gates

1. Add this single pinned encoder/checkpoint and a separately fingerprinted feature representation to pretrained admission and the campaign plan. Keep the corrected fold manifest `8460234d0fcbfd2eb9ca3a3e4165929f50a86acac37d2cd03be1164c2f287fb8`, current eligible cache union, source exclusions and report-admission masks. This is a new representation amendment, not authority inferred from the broad campaign goal.
2. After admission, propose a **CPU-only 32-study extraction pilot**, one nonexclusive node, 16 CPUs, 64 GiB, hard 600 s watchdog; GPU count 0, external spend 0. Choose the existing deterministic batch, report usable selected-slice count, wall time, peak memory and encoder/cache hashes. This research does not launch it.
3. Proceed to full extraction only if count-based projection with **2× pilot time allowance** fits at most 24 CPU node-hours, in resumable jobs of at most six hours and no more than two concurrent jobs. The worst packing bound is 541,184 encoded slices and 1.663 GB of float32 768-dimensional embeddings; this is a bound, not observed load. Require storage checks and completion by October 3 to retain recovery time. Otherwise reject the CPU route; any GPU extraction requires terminal scoring reconciliation and a new exact reservation.
4. Reuse Ticket 44's final-checkpoint, 1,500-successful-step CPU head protocol for all three folds in the paired reference-only/report arm. Reserve complete runs before starting; include image-versus-zero-feature controls. The existing six heads required roughly 964 measured process seconds in aggregate, but the new feature width must be benchmarked. Use one seed and no checkpoint/per-target weight sweep. Report all 58 OOF predictions, paired 2,000-resample study intervals, target support and within-fold direction.
5. Stop if source/data checks fail, the cost ceiling fails, image controls show no signal, or the new representation does not improve the matched local baseline. Even a positive local result needs a concrete delivery/compute plan before addition to the external ensemble. A single prespecified global blend may be evaluated later; an ensemble gain cannot be inferred from standalone AUC or architecture diversity. Gold58-selected external predictions must be described as reused development evidence when assessing blend residuals.

Ticket 44's report arm has OOF 0.6607 versus reference-only 0.6284, delta 0.0323 with interval −0.0075 to 0.0718, and one negative fold. This supports testing useful representation and complementarity without claiming a proven report-label gain. Primary local evidence: [completed comparison](../../artifacts/private/ticket44-full-weak-exposure/analysis-recovery-v1/comparison.md) and [frozen plan](../../artifacts/private/ticket44-full-weak-exposure/plan.json).

## Feasibility before October 11

The exact public full-backbone recipes already exceed current unreserved GPU time on faster publisher hardware; Repair/residual memory also exceeds the historical 25.34 GB A30X allocation. A smaller fully adapted ConvNeXt could cost less, but no measured local throughput, admitted checkpoint, exact public labels or fold-safe recipe establishes its completion cost. Three folds, diagnosis, final fit and delivery must all be budgeted. Allocating one publisher's single-run runtime is insufficient.

The frozen CPU proposal has a plausible calendar path through the October 11 scientific freeze, with **zero additional GPU consumption**, conditional on the bounded pilot and timely queue starts. It can produce a reproducible independent training result using already admitted supervision. Current evidence cannot justify claiming it will close the 0.018 public-score gap or warrant a large encoder-training campaign. Prefer this single representation test over an unbounded reproduction attempt, and preserve room for validated frontier inference/delivery.
