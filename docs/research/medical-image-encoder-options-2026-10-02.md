# Medical image encoder options — 2026-10-02

## Decision

**BiomedCLIP is the only model here worth one prospective, bounded CPU admission.** It has an ungated MIT checkpoint, a native 224-pixel vision tower, and an official implementation that can run without text inputs or an external service. Its medical-domain pretraining includes MRI **figures from scientific articles**; this is not evidence of native knee-MRI pretraining quality, knee abnormality transfer, or a competition gain. MedSigLIP includes native MRI slices but requires gated access and a larger 448-pixel encoder. MRI-CORE is genuinely MRI-specific and publicly reachable, but exact release rights and loading coverage remain unresolved.

Preserve the current full-backbone ResNet experiment and its exact 4,228-study cohort. This note adds resource facts to [the earlier image-learning shortlist](leaderboard-image-learning-options.md); it does not replace that experiment, authorize a weight download, or select a candidate. No weights, fitting, installs, launches, report transmission, quota/ledger changes, or submissions occurred.

## What “medical” establishes

**BiomedCLIP:** The [original paper](https://arxiv.org/html/2303.00915v3) describes 15 million figure-caption pairs from PMC articles, including magnetic resonance images alongside charts, microscopy and other modalities. Composite figures form a substantial part of the corpus. Its major image-classification evaluation includes pathology and **RSNA pneumonia chest X-ray**, while mixed radiology VQA also appears. None is native knee-MRI abnormality evaluation. The [Microsoft model card](https://huggingface.co/microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224) includes a brain-MRI example, which demonstrates usage, not knee transfer. The paper discusses higher-resolution variants; the exact checkpoint above is explicitly **224**, so a paper's 336-pixel result should not silently become this checkpoint's contract.

**MedSigLIP:** Google's [model card](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card) explicitly includes CT/MRI slices in medical pretraining. The [technical report](https://arxiv.org/html/2507.05201v1) identifies **47,622 MRI-US1 slices** in the vision-enhancement/pretraining data and describes selecting slices mentioned with abnormal findings in reports. Published standalone MedSigLIP evaluations concentrate on chest X-ray, dermatology, ophthalmology and histopathology; they do not establish knee-MRI diagnosis performance. Digital **knee X-ray** in the training table must not be relabeled as knee MRI.

**MRI-CORE:** The actual [MRI-CORE paper](https://arxiv.org/html/2506.12186v1) reports Duke-110K: 116,806 volumes and 6.1 million 2D slices across 18 body locations, acquired at one institution, excluding brain/facial anatomy. SAM initialization is adapted using a DINOv2 objective. Musculoskeletal evaluation includes bone and muscle segmentation, and a location classifier whose “knee” class merges knee/lower leg. Those are relevant modality/anatomy facts, **not twelve-target abnormality AUC**. Its README currently mislinks the paper to arXiv **2404.09957**, a different SAM fine-tuning study; this note uses **2506.12186**.

## Practical offline BiomedCLIP vision-only path

Pin **OpenCLIP 2.23.0**, tag commit **`f08f25f3f226bdb538de2b4ed48a9213ba6b179e`**, matching the author's recommended package version. The [official vision wrapper](https://github.com/mlfoundations/open_clip/blob/f08f25f3f226bdb538de2b4ed48a9213ba6b179e/src/open_clip/timm_model.py) builds timm's `vit_base_patch16_224` with `pretrained=False`, retains the backbone's usual pooling when `pool=''`, then applies a learned linear projection to 512. Its backbone output before projection is **768-D**; that is a different representation. The [official `encode_image`](https://github.com/mlfoundations/open_clip/blob/f08f25f3f226bdb538de2b4ed48a9213ba6b179e/src/open_clip/model.py) returns projected features and only L2-normalizes when `normalize=True`; the default is false. Record this choice explicitly.

The exact `open_clip_config.json` supplies `timm_pool=''`, `timm_proj='linear'`, `embed_dim=512`, and CLIP channel means **[0.48145466, 0.4578275, 0.40821073]** / standard deviations **[0.26862954, 0.26130258, 0.27577711]**. These differ from ImageNet normalization. Repeat the existing grayscale cache into RGB and apply the pinned transform; retain its existing anatomical coverage. Replacing it with an unregistered crop or triplet input would add a second experiment.

An offline adapter can instantiate just `open_clip.timm_model.TimmModel` from that configuration and isolate the **`visual.`** tensor namespace from the admitted local checkpoint. It need not instantiate PubMedBERT, tokenize reports, or fetch text assets. The author's full-model configuration references a separate BiomedBERT repository; taking the vision-only path avoids that unnecessary runtime dependency. Both checkpoint and configuration must already be local, and timm/OpenCLIP dependency versions must be recorded in an isolated environment.

The [official checkpoint loader](https://github.com/mlfoundations/open_clip/blob/f08f25f3f226bdb538de2b4ed48a9213ba6b179e/src/open_clip/factory.py) handles a flat state dictionary, an optional `state_dict` wrapper, and a `module.` prefix. **Metadata cannot prove that this exact binary loads with `torch.load(..., weights_only=True)`**, nor which wrapper/prefix it actually uses. A prospective safe admission should attempt that ordinary CPU tensor-only load, reject unsupported objects, then strip only a verified prefix and require `visual.load_state_dict(..., strict=True)` with exact coverage. Do not silently retry unrestricted pickle loading, ignore mismatches, resize position embeddings, or replace the projection with random parameters. Comparing the isolated output with the official visual path is the parity requirement, not assuming equivalent names imply equivalent features.

MedSigLIP also supports genuine image-only extraction: Google's pinned [quick-start notebook](https://github.com/google-health/medsiglip/blob/56b1447e925bb2307a680c1f82d3e34655627208/notebooks/quick_start_with_hugging_face.ipynb) loads `SiglipVisionModel`, takes `pooler_output`, and L2-normalizes it. This avoids text inference but does not remove the checkpoint access gate. Exact processor/config inspection and output width remain admission facts to verify after authorized access; they were not inferred from an ungated sibling model.

MRI-CORE's pinned [builder](https://github.com/mazurowski-lab/mri_foundation/blob/0f4f452614013873f8bb58a1fd613dbe36b58aba/models/sam/build_sam.py) uses `map_location='cuda:0'`, unwraps student/teacher formats, remaps names/positions and loads with `strict=False`. Its [encoder](https://github.com/mazurowski-lab/mri_foundation/blob/0f4f452614013873f8bb58a1fd613dbe36b58aba/models/sam/modeling/image_encoder.py) includes a spatial neck. A usable classifier would require a proven deterministic pooling/state contract. Public source alone cannot establish that every prediction-bearing neck/position tensor is pretrained; changing to 224 pixels also changes the published evaluation recipe. Missing license text, absent checkpoint digest and unverified tensor coverage exclude it from the next admission recommendation.

## One bounded next admission, conditional on current work

After the current ResNet experiment reaches its next independent evidence checkpoint, propose **one BiomedCLIP CPU-only admission**: fetch the single pinned joint checkpoint/config, verify the complete declared hash, strict-load only the vision tower, and run **eight predetermined admitted studies** with original cache membership/masks, microbatch one, fixed 224-pixel FP32 processing and explicit **512-D L2-normalized** output. No fitting, label-informed selection, comparison of alternative layers, or leaderboard request. Use an isolated dependency environment, 16 CPU threads, at most 64 GiB RSS allocation, and a **900-second watchdog**; these are proposed limits, not measured needs.

Require finite nonconstant embeddings, strict state coverage, repeatability, preserved pixel/slot identities, actual peak RSS and valid-slice throughput. Check loader temporary memory separately from steady inference. With the cohort's maximum 128 selected slices/study, 4,228 studies × 128 × 512 × 4 bytes gives a **1,108,344,832-byte** worst-case embedding payload before metadata; actual valid masks determine the real size. Full extraction is justified only after measured completion/delivery cost fits the remaining calendar and resource plan.

If that admission passes, it establishes a usable medical representation and cost, **not predictive gain**. Any later paired comparison must preserve the current supervision/fold policy and report all outcomes. Reused Gold58 is adaptive development, not untouched validation. No original paper or model card here warrants a knee AUC, a >0.961 projection, complementarity with D4, or first-place claim.
